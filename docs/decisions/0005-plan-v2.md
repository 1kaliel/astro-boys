# 0005: Plan v2 — one method, one grid, one data contract

- **Date:** 2026-11-14 20:54 UTC
- **Status:** accepted for roles, stack (FastAPI + SPA) and pilot extent (Northeast Brazil); remaining specifics are defaults that each task owner may change with a diary `DECISION`
- **Deciders:** the team (Kali collects the answers)

## Context

Nine and a half hours into the hackathon, infrastructure and raw data are ready, but there is no pipeline and no
app. Team members researched in parallel and produced six documents that partly disagree:

| Document | Proposes |
|----------|----------|
| Belize 2020 audit (two versions) | VIIRS as reference; event-level matching (Aqua × NOAA-20, ±5 min); per-event models for presence, count and FRP; strict guardrails |
| Technical study | One OLS line converting VIIRS to the MODIS scale; FastAPI + Angular |
| Planning chat | Poisson ratio of sums per cell × month × day/night, pooled toward the region, with a background term; Aqua × S-NPP; H3 grid; static web app |
| Project context | Platform-wise active-cell metric; chronological calibration/validation/test; median anomalies; Google Cloud |
| AGGS | Adaptive hierarchical 4×4 grid, neighborhood analysis, priority index |

Plan v1 also still listed a prediction block the challenge doesn't ask for.

## Decision (proposed)

1. **Method:** MODIS Aqua → VIIRS-equivalent counts per cell and month, by the pooled ratio of sums with a
   background term; calibrate 2012–2019, test 2020–2021; OLS and simpler ratios are baselines in the validation
   table. Spec: [../spec/harmonization.md](../spec/harmonization.md).
2. **Grid:** the AGGS hierarchical 4×4 grid (1° / 0.25° / 0.0625°) is the grid for the whole system.
   Harmonization happens at 0.25°.
3. **Guardrails** from the Belize audit apply everywhere: per-sensor filters, no cross-sensor temperature or
   confidence comparison, no fixed multiplier, origin labels, uncertainty.
4. **Data contract v1:** [../data-dictionary.md](../data-dictionary.md); the dashboard reads `calendar/v1`.
5. **Scope:** must / should / stretch tiers in [../project-plan.md](../project-plan.md#scope). Prediction is out.
   Event-level matching, the AGGS index and drill-down are stretch.
6. **Schedule** rebuilt from Sat 18:30 with checkpoints A (Sat 23:00), B (Sun 02:00), C (Sun 11:00) and
   freeze (Sun 15:00), each with a pre-agreed cut.

## Options considered

| Option | Why not the default |
|--------|---------------------|
| Global OLS (VIIRS → MODIS) | One line ignores day/night, season and region; negative intercept gives negative counts in quiet months; hides small fires. Kept as baseline and display option |
| Event-level models | Best for per-event questions, but the calendar is cell × month; CSVs lack coverage and cloud data; too heavy for 20 hours |
| Active-cell-days as the primary metric | Robust, but the brief asks for hotspot counts. Kept as secondary |
| H3 hexagons | Equal-area and elegant, but adds dependencies on both sides; the degree grid matches AGGS and plain SQL |
| Aqua × NOAA-20 calibration (2018–2025) | Fewer clean years and includes the orbit-drift period |
